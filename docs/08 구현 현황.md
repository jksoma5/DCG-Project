# 구현 현황과 실행 방법

> 2026-09-17 후속 구현: 벤데타 Shift/E는 별도 VendettaLab 씬에 추가했다. 아래 기록은 기존 ControlLab 구현 시점의 내용이며, 최신 벤데타 범위와 실행 방법은 [09 벤데타 구현.md](09%20벤데타%20구현.md)를 참조한다.

작성일: 2026-09-16. 대상: DCG-Project / Unity 6000.5.5f1.

## 구현 범위

06 적용 계획의 첫 실행 묶음인 0-A, 0-B, 1단계와 2단계 그레이브즈 최소 루프를 구현했다.
이 결과는 오프라인 ControlLab이다. 네 직업의 완성된 멀티플레이 게임이나 원작 조작 재현 완료판이 아니다.

| 단계 | 상태 | 결과 |
|---|---|---|
| 0-A 복구 | 완료 | Input System 1.19.0, URP 17.5.0, AI Navigation 2.0.14, Test Framework 1.7.0. Unity 해석과 lock 파일 확인 |
| 0-B 골격 | 완료 | 6개 런타임 asmdef, Editor 1개, EditMode/PlayMode 각 1개. 레이어·입력 맵·직업 정의·명세 표 |
| 1 공통 기반 | 완료 | 명령 경계, 로컬 권위 세션, 단일 고정 틱, CharacterController Motor, 체력·피해·사망, 디버그 표시 |
| 2 최소 루프 | 완료 | 클릭 이동, 실제 A*, 공격·공격 이동·정지, 타깃 추적, 임시 산탄·재장전, 표적 실습 씬 |
| 3~8 | 미구현 | M416, 네트워크 기술 검증, TRG, 벤데타, 직업 선택/대전/품질 보강 |

원작 명세가 없는 수치는 PrototypeTuning ScriptableObject로 분리했고 TuningPending으로 표시했다.
벤데타의 미확인 공격·이동을 새로 만들지 않았다. 입력 맵과 직업 정의만 준비했다.
NGO는 06 계획대로 아직 설치하지 않았다. Networking asmdef는 의도적으로 비어 있다.

## 실행

1. Unity Hub에서 DCG-Project를 Unity 6000.5.5f1으로 연다.
2. Assets/_DCG/Scenes/ControlLab.unity를 열고 Play.
3. 오른쪽 클릭으로 이동/타깃 공격, A 다음 왼쪽 클릭으로 공격 이동, S로 정지.
4. 왼쪽 패널의 Move target은 이동 표적을 움직이고 Reset lab은 전체 상태를 초기화한다.
5. 경로는 청록색 선, 타깃 체력은 머리 위 막대로 확인한다.

Bootstrap 씬으로 실행해도 ControlLab으로 진입한다.
Windows 빌드는 Builds/ControlLab/DCG-ControlLab.exe에 생성한다.

## 구조와 유지보수

- Core: ActorId와 명령/상태/전투 이벤트 계약. GameObject/Camera/Animator 참조 없음.
- Gameplay: 시뮬레이션, 로컬 세션, Motor, A*, 전투·피해. 입력 장치/카메라/NGO 의존 없음.
- Classes: 그레이브즈 명령 정책, 타깃 탐색, Input System 입력.
- Presentation: 로컬 탑뷰, 월드 모델·발사 표현, 개발용 HUD.
- Bootstrap: 위 구성요소를 ControlLab에서 연결. 자동 스모크 프로브는 명시적 실행 인자가 있을 때만 동작.
- Editor: 레이어 설정, 원본 입력/URP 복구 검증, 그리드 굽기, 프리팹·씬 생성, Windows 빌드.
- 설정: Assets/_DCG/Data/Classes/Graves_TuningPending.asset.
- 경로 그리드: Assets/_DCG/Data/Navigation/ControlLabGrid.asset.
- 직업별 ClassDefinition 4개. 실제 활성 직업은 Graves뿐이며 나머지는 playableInLab=false.

DCG > Generate Control Lab은 생성된 DCG 씬·프리팹을 재생성한다. 씬을 직접 편집한 뒤에는 이 메뉴 대신 필요한 항목만 수정한다.
엄폐물을 편집했으면 ControlLab을 연 상태로 DCG > Bake Control Lab Grid를 실행한다.
원본 Assets/Scenes/SampleScene.unity와 Assets/Settings 자산은 삭제하지 않았다. URP 복구 과정에서 일부 설정 자산은 Unity에 의해 마이그레이션되었다.

## 검증 방법

프로젝트 에디터를 닫고 PowerShell에서:
```powershell
.\Tools\Verify-Dcg.ps1 -Build
```

생성 에셋까지 재생성하는 검증:
```powershell
.\Tools\Verify-Dcg.ps1 -Regenerate -Build
```

- EditMode: 경로 우회, 모서리 차단, 도달 불가, 탐색 예산, 잘못된 좌표, 오래된 경로 결과, 체력, 시퀀스, 패키지/입력/직업 자산.
- PlayMode: 입력 없는 명령 이동, 발신자·중복 명령 거절, 피해 중복·공유 설정 분리, 사망 후 정지, 원본 SampleScene, 전투·공격 이동 복귀·엄폐물 우회.
- 테스트 결과와 로그는 Logs/dcg-editmode.xml, Logs/dcg-playmode.xml, Logs/dcg-build.log.
- 실제 빌드 스모크 결과와 화면은 Logs/player-smoke/에 저장한다.

## 현재 한계와 다음 순서

- 모든 조작·전투 수치의 원작 대조는 남아 있다. 자동 테스트 통과는 원작 동일성 검증을 뜻하지 않는다.
- 그리드는 평지·정적 엄폐물용이다. 동적 장애물·복층 이동·경로 작업 스레드는 아직 지원하지 않는다.
- A*는 현재 동기 실행이다. 요청 번호 검사로 경로 교체/정지 후 오래된 결과 적용을 막는 계약을 마련했다.
- 산탄·탄약·재장전은 최소 루프 확인용 임시 규칙이다. 스킬 전체와 고급 카메라 제어는 미구현이다.
- 시야 정책은 공격 차단과 마지막 확인 위치 접근만 구현했다. 완성형 안개/정보 비대칭은 별도 설계가 필요하다.
- 3단계 M416 조작 구현과 RTT/손실 도구 준비 → 4단계 실제 두 클라이언트 네트워크 검증 순서로 이어간다.
- ClassSelect/DuelArena 씬은 실제 선택·대전 기능 구현 시 만든다. 현재는 비어 있는 가짜 플레이 씬을 만들지 않았다.
