# 17 멀티플레이 구현

2026-09-24. Unity 6000.5.5f1 / Netcode for GameObjects 2.13.3 / Unity Transport 2.6.0.

## 실행

- 씬: `Assets/_DCG/Scenes/Multiplayer.unity`. `Control Hub`의 `MultiplayerController`가 접속·선택 화면을 그린다. 실행 시 별도 루트에 NGO `NetworkManager`와 `UnityTransport`를 생성한다.
- 씬 재생성: **DCG > Generate Multiplayer**.
- Windows 빌드: **DCG > Build Windows Multiplayer**, 결과 `Builds/Multiplayer-NGO/DCG-Multiplayer.exe`.
- 두 실행 인스턴스에서 각각 **방 만들기**, **방 참가**를 누른다. 같은 PC는 `127.0.0.1`, 다른 PC는 호스트 주소를 입력한다. 기본 **UDP 7777**.
- 캐릭터 선택 화면의 **바로 시작**을 각자 누르면 그레이브즈·중앙 광장으로 즉시 준비한다. 두 사람의 준비와 로딩이 끝나면 3초 카운트다운 후 전투한다. 상대의 준비를 대신 확정하지 않는다.
- 한쪽만 바로 시작을 선택하면 그쪽은 기본 캐릭터·맵으로 확정되고, 다른 쪽은 일반 선택을 진행한다. 맵이 다르면 기존 추첨 규칙을 적용한다.

직접 IP 연결 방식이다. 인터넷 중계·방 코드·매치메이킹·호스트 이전은 포함하지 않는다. 서로 접근 가능한 UDP 포트가 필요하며 방화벽 설정을 자동 변경하지 않는다.

## 게임 흐름

그레이브즈·벤데타·M416·TRG·폴 중 각자 선택하며 같은 캐릭터도 허용한다. 양쪽 캐릭터 확정 후 중앙 광장/엄폐 전장에 투표한다. 같은 맵이면 그대로 사용하고 다르면 호스트가 두 후보에서 동일 확률로 한 번 추첨한다. 양쪽 로딩 완료 후 시작하며 기본 체력을 사용한다.

호스트가 피해와 승패를 결정한다. 같은 틱에 둘 다 사망하면 무승부다. 두 사람 모두 재대전을 누르면 캐릭터 선택부터 다시 진행한다. 로딩 제한은 60초, 연결 무응답 제한은 10초다. 전투 중 게스트 이탈은 호스트 부전승, 호스트 이탈은 세션 종료다.

## NGO 전환과 지연 처리

자체 TCP 전송을 제거하고 실제 NGO 연결 승인·메시징·서버 시간·RTT 측정과 Unity Transport UDP를 사용한다. 기존 캐릭터 시뮬레이션을 재사용하므로 **NGO CustomMessagingManager**에 입력과 상태를 싣는다. NetworkTransform이나 캐릭터 NetworkObject를 사용한 구조는 아니다.

- 전투 시뮬레이션 60Hz, 이동 전송 및 서버 상태 전송 30Hz.
- 이동·조준·전투 상태는 `UnreliableSequenced`: 누락된 프레임을 기다리지 않고 최신 상태를 반영한다.
- 선택·준비·공격 버튼의 순간 입력·결과는 `ReliableSequenced`: 이동 패킷과 별도로 전달한다.
- 게스트는 자기 캐릭터를 즉시 예측하고, 서버가 처리한 입력 시점의 위치 기록을 기준으로 보정한다.
- 상대 캐릭터는 75ms 보간 버퍼로 표시하며 외삽은 최대 100ms다.
- 체력·탄약·클래스 표현 상태·폴의 반응 상태는 서버 스냅샷으로 동기화한다.
- 전투 상태는 JSON 대신 작은 고정 크기 이진 패킷으로 전달한다. 제어 메시지만 JSON이다.
- 화면에 실제 RTT, 화면 처리 시간, 최근 상태 수신 경과 시간을 구분해 표시한다.

이 변경은 TCP의 재전송 대기와 과거 프레임 재생에 따른 끊김을 줄이기 위한 것이다. 인터넷 경로의 실제 지연을 제거하지는 않는다. 전체 스킬 상태의 결정론적 롤백, 사격 지연 보상, 전용 서버는 구현하지 않았다. 높은 지연에서는 위치·행동 보정이 보일 수 있다.

## 주요 코드

| 파일 | 역할 |
| --- | --- |
| `Networking/DuelRoom.cs` | 선택·바로 시작·맵·준비·결과 상태 |
| `Networking/DuelNgoTransport.cs` | NGO 연결, 승인, 신뢰/비신뢰 메시지, RTT |
| `Networking/DuelInputBuffer.cs` | 최신 이동과 신뢰 입력 분리, 중복·역순 거절 |
| `Networking/DuelMotionHistory.cs` | 예측 위치 보정과 상대 위치 보간 |
| `Bootstrap/Hub/MultiplayerController.cs` | UI와 네트워크 게임 진행 |
| `Bootstrap/Hub/DuelReplicaView.cs` | 서버 상태·캐릭터 표현 반영 |
| `Bootstrap/Hub/ControlHubNetwork.cs` | 캐릭터 생성, 조작 소유권, 서버/예측 진행 |
| `Bootstrap/Hub/DuelMap.cs` | 맵과 경로 탐색 격자 생성 |

입력의 플레이어·Actor ID를 연결의 소유권과 대조한다. 게스트가 좌표·피해·승패를 확정하는 메시지는 받지 않는다. 로컬 Lab·ControlHub·CharacterArena는 기존 로컬 경로를 사용한다.

## 검증

격리된 프로젝트 사본에서 씬 생성, 전체 EditMode/PlayMode, Windows 빌드, 두 실행 파일의 세 경기(역할 교환·맵 추첨·바로 시작)를 실행한다.

```powershell
./Tools/Verify-Multiplayer.ps1 -Smoke
```

`MultiplayerSmokeProbe`는 `-dcgDuelSmoke host|guest`로 실행할 때만 작동한다. 일반 실행에서는 자동 선택·전투가 없다. `Tools/Simulate-DuelNetwork.py`는 로컬 UDP 중계에 지연·지터·패킷 손실을 추가하는 검증 도구다.

2026-09-24 Unity 실제 실행 결과: EditMode **43/43**, PlayMode **89/89** 통과. PlayMode에는 모든 캐릭터 조합과 동일 캐릭터 대전의 양쪽 소유자 검사, NGO 호스트 시작·종료, 패킷 크기·직렬화·보간·위치 보정 검사가 포함된다. 다른 PC와 실제 인터넷 환경의 수동 조작감 검증은 별도로 필요하다.
