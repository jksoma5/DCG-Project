# 멀티플레이 계획

작성일: 2026-09-23
대상: DCG-Project / 두 클라이언트의 1대1 PvP
상태: 2026-09-24 NGO 2.13.3 / Unity Transport 2.6.0으로 전환. 바로 시작(그레이브즈·중앙 광장) 추가. EditMode 43개·PlayMode 89개 통과. 빌드·대전 검증 결과는 프로젝트의 `docs/17 멀티플레이 구현.md` 참조.

## 1. 확정된 게임 흐름

`2명 입장 → 각자 캐릭터 선택·확정 → 각자 맵 선택·확정 → 맵 결정 → 함께 로딩 → 1대1 PvP`

- 각 플레이어는 자신의 클라이언트에서 자신의 캐릭터를 선택한다.
- **바로 시작**을 누르면 그레이브즈·중앙 광장으로 선택을 건너뛰고 즉시 준비한다. 양쪽 모두 준비되어야 시작한다.
- 두 플레이어 모두 캐릭터 선택을 확정해야 맵 선택으로 넘어간다.
- 두 플레이어가 같은 맵을 선택하면 그 맵에서 진행한다.
- 서로 다른 맵을 선택하면 두 맵 중 하나를 같은 확률(각 50%)로 선택한다.
- 선택된 맵에 각자가 선택한 캐릭터로 입장해 대전한다.

## 2. 캐릭터 선택 화면

각 클라이언트에 `내 캐릭터`와 `상대 캐릭터` 영역을 표시한다. 어느 쪽이 방장이든 자신의 캐릭터가 내 영역에 표시된다.

| 영역 | 표시와 동작 |
| --- | --- |
| 내 캐릭터 | 캐릭터 목록, 선택 미리보기, 선택 확정 버튼 |
| 상대 캐릭터 | 상대가 선택한 캐릭터, 선택 중/확정 상태 |
| 진행 상태 | 상대 입장 대기, 상대 선택 대기, 맵 선택으로 이동 |

- 선택 후보: 그레이브즈, 벤데타, M416, TRG, 폴.
- 상대 영역은 확인용이며 내 클라이언트에서 상대의 선택을 변경할 수 없다.
- 선택 요청을 전송한 것과 서버가 확정을 승인한 것을 구분한다. 승인 전에는 확정 완료로 표시하지 않는다.
- 둘의 확정이 서버에 반영되면 같은 맵 선택 단계로 이동한다.

초기 제안: 같은 캐릭터 선택을 허용한다. 선택 중인 캐릭터도 상대에게 공개한다. 확정 후에는 이번 선택 단계에서 변경하지 않으며, 나갔다 다시 방을 만들면 새로 선택한다.

## 3. 맵 선택과 추첨

- 각자 맵 목록에서 하나를 고르고 확정한다.
- 둘 다 확정할 때까지 대기하며, 한 명의 선택만으로 맵을 결정하지 않는다.
- 동일 맵이면 바로 결정한다. 다른 맵이면 서버가 두 후보 중 하나를 한 번만 추첨한다.
- 추첨 결과를 두 클라이언트에 동일하게 전달한다. 각 클라이언트가 따로 난수를 뽑지 않는다.
- 양쪽 화면에 두 사람의 선택과 최종 맵을 표시한 뒤 로딩한다.
- 재전송이나 중복 클릭으로 재추첨하지 않는다. 결정된 맵은 해당 경기 동안 고정한다.
- 등록된 맵 ID만 받으며, 두 클라이언트가 같은 맵 목록과 호환되는 게임 버전인지 입장 단계에서 확인한다.

맵 이름과 실제 구성은 별도 제작 항목이다. 첫 검증에는 서로 구분되는 맵 2개와 각 맵의 플레이어 시작 지점 2개가 필요하다.

## 4. 로딩과 전투

1. 확정된 캐릭터 2개와 맵 정보를 유지하고 양쪽이 같은 맵을 로딩한다.
2. 서버가 두 캐릭터를 서로 다른 시작 지점에 생성하고 소유 플레이어를 지정한다.
3. 양쪽의 맵 로딩과 캐릭터 준비 완료를 확인한다.
4. 공통 시작 시각에 맞춰 카운트다운한 후 이동·공격 입력을 허용한다.
5. 내 캐릭터의 입력과 카메라만 활성화한다. 상대 캐릭터는 전달받은 상태로 표시한다.
6. 서버가 피해·사망·경기 종료를 확정하고 양쪽에 같은 결과를 보여준다.

초기 제안 규칙:

- 3초 카운트다운 후 단판 승부, 상대 체력이 0이 되면 승리.
- 같은 서버 틱에서 둘 다 사망하면 무승부. 한 틱의 전투 처리가 끝난 뒤 결과를 판정한다.
- 전투 중 캐릭터 변경·리스폰은 허용하지 않는다.
- 결과 화면에서 둘 다 재대전에 동의하면 캐릭터 선택부터 다시 시작한다. 한 명이 나가면 방을 종료한다.
- 제한 시간, 체력 배율, 캐릭터별 밸런스는 미확정이다. 기존 아레나의 5배 체력을 PvP 규칙으로 자동 적용하지 않는다.

## 5. 네트워크 역할

초기 구현은 방장 플레이어가 서버 역할도 맡는 호스트 방식으로 제안한다. 접속 메뉴는 `방 만들기 / 방 참가`로 구성하고, 첫 단계에서는 직접 연결로 두 실행 인스턴스를 검증한다. 외부 인터넷 연결을 위한 중계 서비스와 방 코드 방식은 별도 단계에서 정한다.

| 서버가 확정할 정보 | 각 클라이언트가 담당할 정보 |
| --- | --- |
| 참가자 2명, 플레이어별 소유 캐릭터 | 자신의 선택 요청과 조작 입력 |
| 선택 확정 여부, 현재 진행 단계 | 선택 화면, 대기·로딩 표시 |
| 맵 투표와 단일 추첨 결과 | 전달받은 최종 맵 표시 |
| 생성 위치, 전투 시작 시각 | 자신의 카메라와 조작 방식 |
| 전투 시뮬레이션, 피해, 사망, 승패 | 캐릭터 상태 표시, 애니메이션·효과음 |

연결 ID와 플레이어·Actor ID를 서버에서 연결해 상대 조작 요청을 거부한다. 호스트도 동일한 검증 경로를 사용한다. 클라이언트가 보낸 명중·피해·승패 값을 그대로 신뢰하지 않는다. 호스트 방식은 호스트 신뢰를 전제로 하며, 경쟁 서비스용 전용 서버는 후속 검토 항목이다.

공유 상태는 경기 ID, 단계 번호, 참가자별 캐릭터·확정 상태, 맵 투표·확정 상태, 최종 맵, 로딩 준비 상태, 시작 시각, 경기 결과로 구성한다. 지난 경기나 지난 단계의 요청은 무시한다.

## 6. 현재 코드에서 연결할 부분

2026-09-23 로컬 코드 확인 기준:

- `LocalSession`은 `ICommandGateway`를 구현하며 명령 순서와 Actor를 검증한다. 이 경계에 네트워크 입력 전달과 연결 소유권 검증을 추가한다.
- `SimulationWorld`는 현재 `LocalSession`을 직접 생성하고 틱마다 진행한다. 세션을 교체할 수 있도록 분리하고 서버만 권위 있는 전투 계산을 실행하도록 한다.
- `ControlHubArena`는 로컬 캐릭터 전환과 적 AI를 포함한다. 멀티플레이 진입 흐름을 분리하고, 선택된 플레이어 캐릭터 2개만 생성한다.
- F8~F12 캐릭터 전환, F5 전체 초기화, 적 AI 입력은 PvP에서 차단한다.
- 기존 캐릭터별 입력·카메라·전투 규칙은 재사용한다. 원격 캐릭터에는 로컬 입력과 카메라를 활성화하지 않는다.
- 위치·방향·체력·행동 상태를 동기화하고, 발사·피격 효과가 중복 재생되지 않게 이벤트를 식별한다. 지연 대응을 위한 보간·예측·보정은 실제 두 클라이언트 전투 검증과 함께 범위를 결정한다.
- 현재 패키지 목록에는 Netcode for GameObjects가 없다. 네트워크 라이브러리와 호환 버전은 구현 착수 시 공식 문서와 프로젝트 환경으로 확인한다.

## 7. 예외 처리

| 상황 | 초기 처리 제안 |
| --- | --- |
| 1명만 입장 | 상대 대기, 캐릭터 선택 화면 표시 가능, 맵 단계 진입 금지 |
| 세 번째 참가자 | 입장 거절 |
| 잘못된 캐릭터·맵 ID 또는 상대 선택 변경 요청 | 서버에서 거절하고 기존 상태 유지 |
| 중복 확정 또는 지난 단계의 메시지 | 현재 상태를 유지하고 중복 진행·추첨 방지 |
| 선택·로딩 중 연결 끊김 | 경기 취소, 접속 메뉴로 복귀 |
| 로딩 실패 또는 준비 시간 초과 | 경기 시작 금지, 원인 표시 후 접속 메뉴로 복귀 |
| 전투 중 일반 참가자 연결 끊김 | 서버가 남은 플레이어의 부전승 확정 |
| 호스트 연결 끊김 | 세션 종료 표시. 초기 버전은 호스트 이전·자동 재접속 미지원 |

초기에는 선택 제한 시간을 두지 않는다. 로딩 시간 초과 기준은 임시 60초로 두고 실제 빌드에서 조정한다.

## 8. 구현 순서와 완료 기준

| 단계 | 구현 내용 | 완료 기준 |
| --- | --- | --- |
| 1 | 2인 방과 진행 상태 관리 | 두 실행 인스턴스 연결, 3명째 거절, 이탈 처리 |
| 2 | 캐릭터 선택·확정 동기화 | 각자 자기 캐릭터만 선택, 양쪽 확정 후에만 다음 단계 |
| 3 | 맵 2개 등록, 투표·추첨 | 같은 맵은 그대로, 다른 맵은 두 후보에서만 단일 추첨, 양쪽 결과 일치 |
| 4 | 공동 로딩과 캐릭터 생성 | 서로 다른 시작 지점, 같은 캐릭터도 별도 Actor, 양쪽 준비 전 입력 금지 |
| 5 | 전투 동기화 | 두 클라이언트에서 이동·공격·체력·사망·승패 일치 |
| 6 | 결과·재대전·연결 실패 처리 | 재대전 시 이전 투표·입력·결과 초기화, 단계별 이탈 처리 |
| 7 | 지연 환경과 전체 캐릭터 검증 | 호스트/참가자 역할 교대, 다른 캐릭터 10조합과 동일 캐릭터 5조합 검증 |

첫 전투 연결 검증은 그레이브즈 대 M416으로 진행한 뒤 나머지 캐릭터로 확장한다. 최종 완료는 별도 실행된 두 클라이언트가 캐릭터 선택부터 맵 결정, 실제 1대1 전투, 결과 확인까지 연속 수행하는 것으로 판단한다.

검증에는 동일·상이 맵 선택, 중복 패킷에 의한 재추첨 방지, 한쪽 로딩 지연, 상대 Actor 조작 거절, 동시 사망, 각 단계의 접속 종료, 재대전 상태 초기화를 포함한다. 무작위 결과는 몇 번의 실행에서 정확히 반반 나오는지를 요구하지 않고, 두 후보를 동일 확률로 고르는 로직과 결과 공유를 검증한다.
